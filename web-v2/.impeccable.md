# Impeccable Design Context — ShoppingClaw Web

> 本文件由 impeccable 技能的 `teach-impeccable` 流程生成，作为本项目**所有前端设计决策的唯一依据**。
> 修改设计方向时，先改这里，再动代码。

---

## Design Context

### Users

两类使用者，同一套界面，诉求不同：

1. **自用（主用户 = 项目作者本人）**
   - 场景：带着一个模糊的购物需求进来（例："预算 5000 给爸妈买台洗地机，要静音好打理"）。
   - Job to be done：把它拆成可执行的判断——搜商品、比参数、看评价风险、拿到一个**带证据链的推荐**；
     以及长期挂着的六类主动监控（价格 / 库存 / 优惠券 / 排名 / 店铺活动 / Agent 主动总结）。
   - 使用状态：会反复回来、会长时间停留、会盯着 Agent 推理过程看。**不是一次性访问。**

2. **演示（技术面试官 / 评审）**
   - 场景：短时间（几分钟）内判断这个项目值不值得深聊。
   - Job to be done：看懂"多 Agent 可追溯推理"到底强在哪——**派给了谁、拿到什么结论、证据是什么**。
   - 关键：他不会读代码，只会看界面。界面本身就是答案。

### Brand Personality

- **三个词**：精密 · 克制 · 有据
- **情绪目标**：**confidence（可信）**——让人相信这个系统给出的判断是有依据的。
  明确**不**追求 delight（俏皮愉悦）、**不**追求 urgency（紧迫促销感）。
- **语气**：像一个严谨的顾问，不寒暄、不夸自己、每句话都能追溯到来源。

### Aesthetic Direction

- **反参照（最重要）**：**通用 AI 聊天壳**——中间一个对话框、左右大片留白、和 ChatGPT 长得差不多、
  看不出这是一个购物决策产品。**这一条是当前界面的首要问题，任何改动都不得强化它。**
- **正面方向**：精密工具感（Linear 气质）——靠**排版层级、间距节奏、精确对齐**建立专业感，
  而不是靠渐变、发光、毛玻璃等装饰。
- **主题**：**浅色 + 深色两套**，共享同一套语义 token，切换平滑、不重排、不丢层级
  （现状已有 `src/assets/css/base.dark.css`，需重构成语义 token 驱动）。
- **配色禁忌**：
  - 弃用 Ant Design 默认青 `#13c2c2`（现 `--color-accent-500`）——它是"组件库默认脸"的主要来源；
  - 禁止紫蓝渐变、霓虹点缀、深色+发光这套典型 AI 审美；
  - 禁止毛玻璃滥用、圆角+通用阴影的无差别套用；
  - 彩色左边条 callout 卡、胶囊（pill）标签堆砌、用彩色容器表达层级——同属典型 AI 产品的装饰语法。
    层级一律用排版（字号/字重/颜色深浅）与发丝线表达；彩色只用于语义状态文字与关键数据（如成交价）。
- **字体**：建立独立字体系统（展示字体 + 正文字体 + 数据/等宽字体三档），
  弃用 Inter / Roboto / Arial / Open Sans 这类默认栈。

### Design Principles

1. **证据优先于对话（Evidence over chat）**
   界面的主角不是对话框，而是 **Agent 派发轨迹 + 证据链**。聊天只是输入入口。
   现状已有 `AgentFlowPanel` / `ThinkingProcessSidebar` / `ToolCallCard`，应把它们从"侧边附属"
   提升为**视觉重心**。

2. **可追溯必须看得见**
   「派给了谁 → 拿到什么结论 → 依据是什么」这三段必须在一个屏幕内可展开、可回看。
   这是产品相对"单轮问答"的核心差异点，也是面试官唯一关心的东西。

3. **克制的专业感**
   信任感来自**精确**：对齐、间距节奏、字号层级、状态语义清晰。
   不使用装饰性渐变 / 发光 / 投影堆砌；动效只服务于状态变化，不用于炫技。

4. **信息密度，而非留白表演**
   购物决策需要横向对比参数（价格、规格、风险评分）。
   要能一眼扫到多维信息，**反对**为了"高级感"把内容稀释成大留白。

5. **双主题语义一致**
   浅色 / 深色只切换语义层 token（`--color-surface` / `--color-text` 等），
   原始色板保持不变；切换不得导致层级丢失或对比度不达标（WCAG AA）。

## 与后端的接口面（前端改写时必须对齐）

- 聊天走 **SSE 流式**（`POST /api/chat/agent/{agent_id}`），事件序列：
  `init → thinking → tool_start → tool_complete → answer* → done`，另有 `title` / `error` 事件。
- 认证：`Authorization: Bearer <JWT>`；端点 `/api/auth/register`、`/login`、`/me`。
- 会话：`GET /api/chat/conversations`、`GET /{thread_id}`、`DELETE /{thread_id}`。
- 演示技巧：主动监控可调用后端 `trigger_now()` 立即触发一次，不必等 cron。
