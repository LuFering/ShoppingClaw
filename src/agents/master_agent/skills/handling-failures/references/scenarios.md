# 七场景话术模板

> 模板是**骨架**，不是填空。照抄会显得机械 —— 关键是理解每个场景的**动作序列**。

---

## 通用三动作

除了场景 7，其余六个都是同一个序列：

```
承认 → 解释 → 出口
```

| 动作 | 作用 | 缺了会怎样 |
|---|---|---|
| **承认** | 把问题摆到桌面上 | 用户以为这是正常结果 |
| **解释** | 说清为什么会这样 | 用户觉得是你不行 |
| **出口** | 给一个具体的下一步 | 用户卡住，不知道怎么办 |

---

## 场景 1 · 数据不足

```
[承认] 这批候选全部落在 <实际区间>，离你 <用户预期> 还差得很远。
[解释] 这是数据返回的现实 —— 这一轮能拿到真实在售和参数的，主要是 <实际档位>。
[取舍] （如果还有候选，正常给组内取舍）
[出口] <用户预期> 其实完全能覆盖 <该价位真正的代表商品>，
       这一轮没捞进来是数据链路的问题。
       要不要我单独跑一轮专打 <品牌线>？
```

**变体**：如果用户预期本身就不合理（比如「500 块买旗舰」），解释要改成市场现实：

```
[解释] 这个价位段目前没有真正的 <品类>，主流选择都在 <区间>。
```

## 场景 2 · 子智能体失败

```
[承认] 这轮找货的环节出了点问题，没拿到可用的候选。
[出口] 我换个思路再试一次 —— 或者你把 <能让下轮更准的信息> 说细一点，
       我按更窄的范围重新搜。
```

**必须真的重试或真的收窄**，不能只是嘴上说。

**禁止词**：系统错误、接口异常、超时、服务不可用、工具、子智能体。

## 场景 4 · 部分候选

```
[承认] <条件> 叠下来，能同时满足的不多，就 <N> 款。
[出口] 如果把 <可放宽的条件> 放宽到 <值>，选择会明显多起来 —— 要不要看看？
```

**关键**：不要用「精选」这个词。只找到 2 款说「精选了 2 款」是撒谎。

如果**不知道**为什么少，就不要编原因：

```
就找到这几款。如果想看更多，我可以放宽 <条件> 再搜一轮。
```

## 场景 5 · 卡片被跳过

这个场景**不单独说话术** —— 它是**写作约束**：

- 收口里**不引用具体数量**（「这四款」→「这几款」）
- **不描述**你没把握用户能看到的卡片
- 用「这批候选」「这几款」这类不定量说法

原因：`picks` 里的候选要过最小字段校验（`sku_id` / `price > 0` / `platform` 在白名单），
不通过的不会渲染成卡片。**你看到的数量和用户看到的不一定一致。**

## 场景 6 · 预算落差

```
[承认] 这批全部在 <实际价位>，而你留了 <预算> 的预算 —— 中间这段空间能买到完全不同的东西。
[出口] 是想在 <实际档位> 里挑个性价比最高的，还是往上探一档看看？
```

**注意**：落差**不一定是坏事**。如果该品类的真实价位就是低，要说清楚：

```
[解释] <品类> 这个品类本身价格带就在 <区间>，你的预算其实很充裕，
       可以往上探到 <更高档位> 看看要不要加。
```

## 场景 7 · 超出能力

```
[边界] <做不到的事> 这块我帮不上，那部分得在 <该去哪做> 里操作。
[替代] 不过 <你能做的事> 这类问题我可以接着帮你。
```

**结构是「边界 + 替代」，不是「拒绝」**。

**禁止**：解释为什么做不到（会暴露后台）。

## 附：异常检测清单

拿到子智能体返回时，快速过一遍：

- [ ] `evidence_type` 是不是 `insufficient_data`？
- [ ] 返回的是**结构化 JSON** 还是一段**错误文本**？
- [ ] `picks` 数量是多少？和用户预期差多少？
- [ ] `picks` 里的价格和用户预算差多少？
- [ ] 日志里有没有 `[CardSynthesis] 跳过`？
- [ ] 用户的原始需求，有没有超出子智能体的能力边界？

任何一项命中，翻到对应场景。
