# 搭配与顺序兼容

一整套买东西，风险不在单件，在**它们之间**。查两件事：

## 什么时候用
- 一次要买**一整套**，需要确认各项能否配到一起
- 用户问「这两个能不能配 / 先买哪个」

## 什么时候不用
- 只买一件 → 走选购技能
- 清单还没拆 → 先 `clarifying-needs`
- 只是比价 → `hunting-deals`

---

## 1. 搭配兼容（能不能装到一起）

| 查什么 | 例 |
|---|---|
| 尺寸 | 家电放得进预留位吗；家具进得了门 / 电梯吗 |
| 接口 / 协议 | 智能设备同不同生态；支架孔距对不对 |
| 规格 / 功率 | 插座够不够；总功率会不会跳闸 |

**查不出的标「待确认」**，写清「确认什么、找谁、不确认会怎样」——
只说「尺寸待确认」等于没说。

---

## 2. 顺序依赖（先买哪个）

组合采购的独有约束：**A 没定，B 就买不了**。

- 硬装没完成 → 家电尺寸定不了 → 不能下单
- 尺寸没量 → 定制家具做不了 → 工期顺延

> **数据前提**：依赖关系必须来自用户确认或工具返回；**推断出的依赖标「待确认」**，不当作事实。

这类依赖**必须写成显式的顺序**（在清单顺序里标「依赖 X」），
不能只在风险区顺带提一句。

---

## 3. 不要做的事

- **不编依赖**：没确认的依赖标「待确认」，别编因果链
- **不假设尺寸**：没量过的就说没量，别默认"应该没问题"
- **不重复**：同一条依赖不在清单、顺序、风险区各写一遍
- **不越权**：你给「能不能配 / 先买哪个」的结论，买不买用户定

---

## 自检清单

- [ ] 搭配三查（尺寸 / 接口 / 规格功率）都过了吗
- [ ] 查不出的标「待确认」，写清确认什么 / 找谁 / 不确认会怎样了吗
- [ ] 依赖关系写进显式顺序了吗（不是只在风险区提一句）
- [ ] 推断出的依赖标「待确认」而不是当事实了吗
- [ ] 没有假设尺寸、没有编依赖吗
