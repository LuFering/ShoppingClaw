# 需求收敛

用户说「想装修」「搬家要置办」时，**别急着搜** —— 先把**模糊需求**变成**字段**。

## 什么时候用
- 用户只说「想装修 / 要搬家 / 开学置办」这类**模糊目标**
- 缺面积 / 户型 / 预算等**拆清单必需的字段**

## 什么时候不用
- 需求已经具体（品类 / 预算 / 场景都说清了）→ 直接往下走
- 只问单个商品 → `evaluating-fit`

---

## 1. 收敛成三样东西

| 产出 | 例（"想装修"） |
|---|---|
| **对象清单** | 硬装 / 家电 / 软装 / 家具… |
| **硬约束** | 预算、面积、户型、时限 |
| **场景背景** | 自住/出租、有无老人小孩、所在地 |

没有「面积 / 户型 / 预算」，清单拆不出来，也搜不准。

---

## 2. 该问什么、不该问什么

- **影响拆解的，优先问**：面积、户型、预算区间、自住还是出租
  —— 但拿不准是否影响拆解时，先给方向、把问题放末尾，**不强制追问**
- **只影响细微偏好的，先别问**：颜色、品牌倾向 —— 先出方向，末尾再补问
- **能推断的，别问**：说"三居室"就不用问"几室"

**一次最多问 1–2 个**，且要带选项，不要开放式提问。

---

## 3. 收敛完就往前推

字段够了（能拆清单、能搜），立刻进入拆清单 / 搜索，
**不要**为了"信息更全"一直问 —— 把"想装修"问成二十问，用户会跑。

---

## 4. 不要做的事

- **不连环问**：用户答过的、能推断的，不再确认一遍
- **不只问不答**：即便要澄清，也先给出"你可能需要这几类"的方向
- **不把偏好当硬约束**：颜色/品牌是软信息，别塞进硬约束字段

---

## 自检清单

- [ ] 产出了对象清单 / 硬约束 / 场景背景三样吗
- [ ] 只问了影响拆解的字段（≤ 1–2 个、带选项）吗
- [ ] 没把颜色 / 品牌这类软偏好当硬约束吗
- [ ] 够了就往前推，没有连环追问吗
- [ ] 没有只问不答吗
