# 单品适配评估

用户给一个商品问「值不值 / 适合我吗」时，要评的是**它对你的场景合不合适**，
不是「它本身好不好」。同一件东西，对 A 是理性之选，对 B 是浪费。

> **数据前提**：本技能只在用户**明确给出商品信息**（链接/型号/规格）时使用。
> 规划工具链拿不到单品详情时，相关判断标「待确认」，不要凭印象评估。

## 什么时候用
- 用户给了**一个具体商品**（链接/型号/规格），问「这个值不值 / 适合我吗」
- 要在「买它 or 不买」上给判断

## 什么时候不用
- 还没有候选 → 先 `searching-products`
- 有两个以上候选要选 → `comparing-products`
- 清单还没拆 → 先 `clarifying-needs`
- 问的是价格贵不贵 → `hunting-deals`

---

## 1. 先锁定「场景约束」——没有它无从判断

判断合不合适，前提是知道「什么场景」。先抽出这三样：

| 约束 | 问什么 |
|---|---|
| 用途 | 买来干什么？什么频次、什么环境 |
| 硬约束 | 尺寸 / 预算 / 兼容 / 已有设备 |
| 最在意 | 这个人最不能妥协的是什么 |

**若用户没给场景**（只丢一个链接说"这个怎么样"）：
先按最可能的场景给一版判断，末尾补一句「如果主要是 XX 用途，结论会不同」——
**不要**停下来只问不答，也别假装有场景信息。

---

## 2. 只评三件事（不堆参数）

| 评什么 | 判据 |
|---|---|
| **核心需求** | 这个场景里最重要的一两个点，它满足吗 |
| **硬约束** | 尺寸/预算/兼容——不满足就是一票否决 |
| **致命短板** | 它最大的短板，会不会正好踩中这个场景的雷 |

短板是否"致命"取决于场景：户外用，防水差就是致命；放家里，就只是取舍。

---

## 3. 输出：结论 + 依据 + 前提

**必须有前提**，因为"合不合适"是场景相关的：

> 「如果是通勤降噪，这款合适——降噪够用、佩戴稳；但要是长时间办公戴，
> 入耳式可能胀耳，那就不如半入耳。」

- **结论明确**：合适 / 不合适 / 看情况（看什么情况，说清）
- **依据落在场景点上**：不是参数，是「对你的用途意味着什么」
- **短板说清**：不藏，但要说它对这个场景要不要紧

---

## 4. 拿不到关键信息时

- 价格/规格工具没返回 → 标「待查」，**不要编**
- 用户没说场景、又明显影响结论 → 给一个假设版本 + 问一句
- 商品信息不全 → 说明缺什么、缺了影响哪个判断

---

## 5. 不要做的事

- **不评"好不好"**：只评"合不合适"——好坏是绝对的，合适是相对的
- **不堆参数**：列一堆参数 ≠ 评估
- **不加绝对结论**：「闭眼买」需要场景与依据都支撑
- **不越权**：给判断与依据，买不买用户定
- **不替代对比**：如果用户其实在"几选一"，走 comparing-products，不是这个

---

## 自检清单

- [ ] 锁定了场景（用途 / 硬约束 / 最在意）吗
- [ ] 有硬约束一票否决吗
- [ ] 短板说清「对这个场景要不要紧」了吗
- [ ] 结论带「前提」了吗（合适 / 不合适 / 看情况）
- [ ] 拿不到的数据标「待确认」，没有编造吗
