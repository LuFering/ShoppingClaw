# 候选横向对比

对比的目标不是「哪个参数高」，而是**在用户的硬约束下，哪个最不容易买错**。
先把不合格的淘汰，再在合格的里选 —— 不要一上来就比参数。

## 什么时候用
- 某个采购对象已有 **2 个以上候选**，需要定下选哪个
- 用户问「这几个怎么选 / 哪个更好」

## 什么时候不用
- 还没有候选 → 先 `searching-products`
- 只给了一个商品问值不值 → `evaluating-fit`
- 清单还没拆完 → 先 `clarifying-needs`
- 问的是价格 / 优惠 → `hunting-deals`

---

## 1. 先用硬约束淘汰

对比前，把不满足**硬约束**的候选直接删掉：

| 硬约束 | 判据 |
|---|---|
| 尺寸/空间 | 放不下、装不上 |
| 规格/接口 | 与现场不匹配（电压、接口、尺寸） |
| 预算上限 | 单价超出该项预算 |
| 平台 | 非淘宝/拼多多 |

淘汰要**写理由**（如「尺寸超标 2cm」），不要默默删 —— 用户要看得见为什么没考虑它。

---

## 2. 剩下按「取舍维度」比，不堆参数

先找出这类东西**决定性的 2–3 个取舍维度**（互相矛盾、必须二选一的），再横向排开：

| 维度类型 | 典型对立 |
|---|---|
| 性能 vs 价格 | 吸力更强 vs 更便宜 |
| 一体 vs 分体 | 省地方 vs 更好用 |
| 一次性 vs 长期成本 | 入手便宜 vs 耗材便宜 |

> **数据前提**：尺寸 / 规格 / 平台 / 历史价 / 券叠加，**只认工具返回的值**。
> 工具没返回的，一律标「待确认」，**不做比较、不下结论**。

**严禁**把「同向堆料」参数当取舍维度（降噪-45dB、Hi-Res 金标都是"更好"，
不构成取舍），那只会让对比表变长、还看不出该选谁。

---

## 3. 输出：首选 + 备选 + 淘汰理由

| 位置 | 写什么 |
|---|---|
| **首选** | 1 款，一句话落在取舍点上：「在你这个约束下选它，是因为…」 |
| **备选** | 1 款，写清「什么人 / 什么情况会选它」 |
| **淘汰** | 逐条给理由（硬约束淘汰的 + 比较后落选的） |

**个数纪律**：表里最多留 3–4 款。给多了用户反而选不出。

---

## 4. 比不出来时怎么办

几款在关键维度上**几乎一样**时：

- **不要**硬编一个"综合最优" —— 那是假精确
- 如实说「这几款差别很小」，给一条最简单的规则：「预算够选 A，想省选 B」
- 差异在非参数项（到货、售后、平台）时，说清让用户按偏好定

---

## 5. 不要做的事

- **不堆参数**：表里只放取舍维度，同向参数不作维度
- **不编价格**：价格须来自真实返回，拿不到就标「待查」
- **不给绝对结论**：「一定选这款」要有取舍依据支撑
- **不替代用户**：你给首选 + 理由，拍板是用户的事

---

## 自检清单

- [ ] 先用硬约束（尺寸/规格/预算/平台）淘汰了吗
- [ ] 每条淘汰都写了理由吗
- [ ] 对比的是「取舍维度」，不是同向堆料参数吗
- [ ] 首选 / 备选各 1 款、表里 ≤ 3-4 款吗
- [ ] 价格都来自真实返回、拿不到标「待查」了吗
- [ ] 没有编造参数、没有硬编「综合最优」吗
