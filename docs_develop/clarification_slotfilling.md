## 澄清 vs 追问

本质区别一句话：

> **澄清**是”我没听懂你说什么” → 追问是”我听懂了，但信息不够”

-----

### 触发条件不同

|      | 澄清（Clarification） | 追问（Slot Filling） |
|------|-------------------|------------------|
| 触发原因 | 意图不明确/置信度低/多意图冲突  | 意图明确，但必填槽位缺失     |
| 发生阶段 | 意图识别之后，路由之前       | 路由之后，执行之前        |
| 问题指向 | 用户想做什么            | 用户想怎么做           |

-----

### 对话示例对比

**澄清场景**

```
用户：帮我处理一下那个订单
系统：【意图识别置信度低，order_cancel 0.45 vs order_modify 0.42】

→ 澄清：您是想取消订单，还是修改订单信息？
```

**追问场景**

```
用户：帮我订明天去上海的机票
系统：【意图=book_flight 0.95，缺失槽位 cabin_class】

→ 追问：请问您需要经济舱还是商务舱？
```

-----

### 系统内部处理逻辑不同

```
澄清流程：
用户输入 → 意图识别(低置信/歧义) → 主Agent介入 → 
生成澄清问题 → 等用户回答 → 重新走意图识别

追问流程：
用户输入 → 意图识别(高置信) → 路由到子Agent → 
子Agent检查槽位 → 生成追问 → 等用户回答 → 
补充槽位 → 继续执行（不重新识别意图）
```

关键差异：**澄清后要重新过意图识别，追问后只补槽位直接继续执行**。

-----

### 在 Agent 架构里的位置

```
用户输入
  ↓
意图识别模块
  ↓
置信度判断
  ├── 低置信/歧义  →  【澄清】主Agent处理，结果重新入队
  └── 高置信       →  路由到子Agent
                         ↓
                      槽位完整性检查
                         ├── 缺必填槽  →  【追问】子Agent处理，补完继续
                         └── 槽位完整  →  调用工具执行
```

两者是串联的两道关卡，澄清在前，追问在后，都通过才执行。
