## 0. 总览：一条消息的完整旅程

```
POST /api/chat/agent/{agent_name}          ← 前端发起（body: query / config.thread_id / meta）
   │
   └─ chat_agent()                          server/routers/chat_rounter.py:113
        └─ stream_agent_chat(...)           server/services/chat_stream_service.py  ★ 待实现
             │
             ├─ MasterAgent.get_graph()     src/agents/master_agent/graph.py
```

## 2. 逐事件字段对照（实测字节 → 后端填法）

### 2.1 `message_chunk` —— 最容易做错的一个

**前端实测载荷**：
```json
{ "content": "收到。我理解", "message_id": "round-1-s1" }
```

**前端行为**（`AgentChatComponent.vue:1284`）：按 `message_id` 归并 AI 消息；同 id 的增量累加进同一条气泡。

> ### ⚠️ 红线：`message_id` 的粒度 = UI 上一个气泡，不是「一次 LLM 轮次」
>
> 这是**踩过两次坑**的地方，后端必须照此实现，否则前端怎么改都白搭。
>
> **规则：一个气泡 = 一段前置文本 + 它引出的那个状态块（`tool_start`）。**
>
> - 只有 `tool_start` 才推进 `message_id`；纯文本段一律沿用「当前 id」。
> - 反例 A：所有前导文本共用 `round-1` → 全被拼成一大段文字。
> - 反例 B：每句话一个新 id → 开篇正文与紧随其后的口播之间没有状态块，会被切成两条空对空的气泡。
>
> **后端实现建议**：在 `stream_agent_chat` 里维护一个 `narrator` 计数器，
> **只在即将发出 `tool_start` 时** `narrator += 1` 并生成新 id；文本段复用当前 id。

**参考实现（Python 伪代码）**：
```python
class Narrator:
    def __init__(self, base: str):
        self.base, self.n = base, 0
    def next(self) -> str:
        self.n += 1
        return f"{self.base}-s{self.n}"
```

**字段来源对照**：

| 字段 | 后端来源 | 备注 |
|---|---|---|
| `tool_call_id` | `request.tool_call["id"]` | `sse_monitor` 已填；**某些 provider 不返回 id → 必须兜底生成**，否则前端无法归并 |
| `tool_name` | `request.tool_call["name"]` | 已填 |
| `arguments` | `request.tool_call["args"]` | 已填 |
| `duration_ms` | `time.time() - start_time` | 已填 |
| `result_preview` | 结果前 500 字 | 已填 |
| `result_content` | `_serialize_tool_result(result)` | 已填；**下游渲染器靠解析它拿结构化数据** |
| `meta` | `registry.get_meta(name)` | 已填，**但见下方 ⚠️** |
| `message_id` | **须由 `stream_agent_chat` 注入** | ⚠️ `sse_monitor` 当前**没发** `message_id` |
| `subagent_run` | 见 §3 | ★ 待补 |
| `orchestration` | 见 §3 | ★ 待补 |
| `drill` | 见 §4 | ★ 待补 |

> ### ⚠️ 三个必须修的对接缺口
>
> **① `message_id` 缺失**
> `sse_monitor.wrap_tool_call` 的 emit 里没有 `message_id`。
> 没有它 → 前端把所有工具挂到 `__local__` 兜底条目 → **工具卡不跟随气泡**。
> **修法**：`SSEMonitoringMiddleware` 需要能从 context 读到当前 `narrator` 的 id 并写进事件。
>
> **② `meta.icon` 是 emoji，前端不认**
> 后端 `registry.py:34` 注释写 `icon: str = ""  # emoji 图标`；
> 前端 `BaseToolCall.vue` **根本不读 `meta.icon`** —— 图标由 `toolRegistry.js` 按 **tool_name** 映射 lucide 组件。
> **结论**：`meta` 是装饰性的，**不要求后端对齐**；真正决定渲染的是 `tool_name`。
> 但这意味着 **`tool_name` 必须与前端 `TOOL_RENDERERS` 的 key 完全一致**，否则卡片降级成通用样式。
>
> **③ 前端只认 `tool_name` 做渲染路由**
> 必须对齐的名字（`web-v2/src/components/ToolCallingResult/ToolCallRenderer.vue`）：
> `orchestrate` / `task` / `ask_user` / `ask_user_question` /
> `search_products` / `render_product_card` / `render_comparison` /
> `save_to_archive` / `update_record_phase` / `set_reminder` / `write_review` /
> `chart` / `draw_chart`

## 3. 两个「富载荷」字段 —— 卡片的血肉

### 3.1 `orchestration`（`orchestrate` 卡）

**渐进显形**：后端**不能一次性把整份轨迹发完**，否则卡片「瞬间长满」，毫无执行感。

**机制**：**复用同一个 `tool_call_id`，分 6 次发 `tool_start`，每次多露出一个分区。**

分区顺序（契约常量 `ORCHESTRATION_REVEAL_STEPS`）：
```
['intent', 'skills', 'rag', 'mcp', 'dispatch', 'decision']
```

实测显形路径：
```
i-----  →  is----  →  isr---  →  isrm--  →  isrmd-  →  isrmdD
意图分诊    +Skill     +RAG      +MCP      +派遣      +决策
```

**后端产出者**：`MasterAgent` 的编排决策链。建议在意图分诊 / 检索 RAG / 问注册中心 / 决定派遣
四个节点各自完成时，各 emit 一次同 `tool_call_id` 的 `tool_start`。

**字段表**（`orchestration` 对象）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | number | 契约版本，当前 `1` |
| `status` | string | `running` \| `completed` \| `failed` |
| `step` | number | **0-based 已显形分区数**；缺省视为全显形（向后兼容） |
| `intent` | object | `{ type, label, confidence, slots:{target,budget,forWhom,scenario,phase}, need_clarify:[] }` |
| `skills` | array | `[{ id, name, detail }]` |
| `rag` | array | `[{ id, collection, name, query?, detail }]` |
| `mcp` | array | `[{ id, server, method, name, detail }]` |
| `dispatch` | array | `[{ slug, task, depends_on:[], timeout_ms, parallel }]` |
| `decision` | string | 一句话派遣决策 |
| `guardrails` | object | `{ touched_business_data: boolean, note: string }` |

> ### ⚠️ 未显形的分区必须下发**空值**（`null` / `[]` / `""`），不能省略键
> 省略键会让下游分不清「还没到」和「本就没有」，契约会漂移。

### 3.2 `subagent_run`（`task` 卡）

**同样渐进显形，但它是「容器型」**：子智能体干活期间，它的卡片要持续更新，
中间夹着子智能体内部的业务工具事件 —— 这是**设计使然**（已写进验证脚本的判据）。

**实测增长**（购前助手）：`已跑工具数 = [0,0,0,1,2]`、`已查 RAG = [0,1,2,2,2]`

**字段表**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | string | `running` \| `completed` \| `failed` |
| `skills` | array | `[{ name }]` —— 派遣时就亮出 |
| `rag` | array | `[{ name, detail, done }]` —— `done:false` 渲染成**脉冲加载点** |
| `tools` | array | `[{ name, detail, done }]` —— **已执行**的工具，随执行逐个追加 |
| `plannedTools` | array | `[{ name, detail, done }]` —— **打算执行**的，先亮出来 |

**后端产出者**：`SubAgentMiddleware`。每次子智能体内部工具完成，就重发一次同 `tool_call_id` 的 `tool_start`，
把新工具追加进 `tools` 并把 `plannedTools` 里对应项标 `done: true`。

**子智能体标识**：`arguments.subagent_type`（前端 `setToolCallDrill` 靠它反查）。
后端 `subagents.yaml` 里的 key 是 `researcher` / `analyst` / `critic` / `memory_manager` ——
**与前端 mock 用的「购前助手 / 购后助手」不一致，需要映射或在 yaml 里改对**。

## 4. `subagent_drill` —— 全新事件，必须新增

```json
{ "slug": "购前助手", "action": "expand", "description": "按偏好找候选、比价、出商品卡", "message_id": "round-1-s2" }
```

| 字段 | 说明 |
|---|---|
| `slug` | 子智能体标识，**必须与 `task` 的 `arguments.subagent_type` 一致** |
| `action` | `expand`（开始干活前，展开卡片让用户看见内部过程）/ `collapse`（干完后收起） |
| `description` | 可选 |
| `message_id` | 归属气泡（前端不用它定位，但保持契约完整） |

**前端行为**：`setToolCallDrill()` 倒序找 `name === 'task' && args.subagent_type === slug` 的卡片，
打上 `drill` 标记 → `BaseToolCall` 用 `watch` 响应。

**注意**：
- `subagent_drill` **不切气泡**（它自己没有卡片）；且它**只改标志、不迁移工具卡所在条目**。
- **只写标志，不当场改展开态** —— 用户手动折叠不会被覆盖。

**后端产出者**：建议在 `stream_agent_chat` 里监听 `SubAgentMiddleware` 的启动/结束回调。

## 5. `stream_agent_chat` 骨架（可直接开工）

```python
# server/services/chat_stream_service.py
import json, time, uuid
from typing import AsyncIterator

from src.services.sse_protocol import EventType
from src.services.sse_session_manager import get_session_manager


class Narrator:
    """气泡边界 = 状态块。只在 tool_start 前推进 id，文本段复用它。"""
    def __init__(self, base: str):
        self.base, self.n = base, 0
    def next(self) -> str:
        self.n += 1
        return f"{self.base}-s{self.n}"


async def stream_agent_chat(*, agent_name, query, config, meta, image_content,
                            current_user, db) -> AsyncIterator[str]:
    thread_id = config.get("thread_id") or str(uuid.uuid4())
    mgr = get_session_manager()
    await mgr.create_session(thread_id)
    narrator = Narrator(f"round-{meta.get('round', 1)}")

    async def emit(t, **payload):
        await mgr.emit(thread_id, {"type": t.value if hasattr(t, "value") else t, **payload})

    # ① init
    await emit(EventType.INIT, thread_id=thread_id, request_id=meta.get("request_id"))

    try:
        from src.agents.master_agent.factory import get_master_agent  # 按实际入口调整
        agent = get_master_agent()
        graph = await agent.get_graph()
        # 从 MasterAgent 取到 sse_monitor 实例，让它的事件能带上 message_id
        agent.sse_middleware.set_narrator(narrator)   # ★ 需在 sse_monitor 里加这个钩子

        async for ev in graph.astream_events(
            {"messages": [{"role": "user", "content": query}]},
            config={"configurable": {"thread_id": thread_id}},
            version="v2",
        ):
            kind = ev["event"]

            # ② 正文流式
            if kind == "on_chat_model_stream":
                chunk = ev["data"]["chunk"]
                text = getattr(chunk, "content", "")
                if text:
                    await emit(EventType.MESSAGE_CHUNK,
                               content=text, message_id=narrator.current())  # ★ 复用当前 id

            # ③ 编排卡：按四个决策节点各推进一档 step
            elif kind == "on_chain_end" and ev["name"] in ORCH_NODES:
                await push_orchestration_step(ev, narrator, emit)

            # ④ 子智能体启动/结束 → subagent_drill
            elif kind == "on_chain_start" and ev.get("metadata", {}).get("is_subagent"):
                await emit(EventType.SUBAGENT_DRILL, slug=..., action="expand",
                           description=..., message_id=narrator.current())
            elif kind == "on_chain_end" and ev.get("metadata", {}).get("is_subagent"):
                await emit(EventType.SUBAGENT_DRILL, slug=..., action="collapse",
                           message_id=narrator.current())

        # ⑤ done
        await emit(EventType.DONE, statistics={
            "total_tokens": ..., "elapsed_ms": ...,
            "time_cost": round(elapsed, 1),        # 秒
            "total_tool_calls": ..., "failed_calls": ...,
        })

    except Exception as e:
        await emit(EventType.ERROR, message=str(e))
        raise
```

**注意**：`event_generator` 已负责把 dict 封成 `id:/event:/data:` 的 SSE 文本并支持断点回放，
所以 `stream_agent_chat` **返回的是 `emit` 后的队列消费**，或直接把 `mgr.event_generator(thread_id)` 交给 `StreamingResponse`。二选一，不要重复封帧。

## 6. 落地顺序建议（每步都可独立验收）

| 步骤 | 做什么 | 验收标准 |
|---|---|---|
| **S1** | `stream_agent_chat` 打通 `init` + `message_chunk` + `done` | 页面能收到 AI 正文，气泡按 `message_id` 正确切分 |
| **S2** | 接 `sse_monitor` 的 `tool_start`/`tool_complete`，**补 `message_id`** | 工具卡挂到正确气泡下 |
| **S3** | `plan` / `plan_update` 接 `TodoListMiddleware` | 待办区不再是「暂无计划步骤」 |
| **S4** | `orchestrate` 卡 + `orchestration` 字段 + **渐进 step** | 编排卡逐段长出来（6 段） |
| **S5** | `task` 卡 + `subagent_run`（含 `plannedTools` / `done`） | 子智能体执行详情随进度点亮 |
| **S6** | **新增 `subagent_drill`** | 子智能体卡片自动展开/收起 |
| **S7** | `thinking` + `statistics` + `title` | 右侧面板统计有数 |
