# Skill 设计规范

给主智能体 / 子智能体增加或修改 Skill 时，先读这一页。
它回答一个判定问题：**一项能力，应该放提示词、放 Skill、还是放工具？**

相关：[AGENTS.md](../../AGENTS.md)（协作公约）。技能运行机制（挂载链路、
渐进披露、「使用 Skill」前端联动）的代码事实见
`src/agents/common/middleware/skills.py` 与 `src/agents/master_agent/graph.py` 的注释。

## 1. 载体三分

| 载体 | 本质 | 例子 |
|---|---|---|
| System Prompt | 定义身份、职责与**每轮都要执行**的规则 | 「不得编造商品参数」「派遣简报只给业务目标」 |
| Skill | **按需加载**的一类场景的完整方法：步骤、判据、产出物、判例 | 「对比两款怎么写」「同款差价怎么辨」 |
| Tool | 让模型真正执行操作 | 搜索商品、查价格、写档案 |

判断口诀：**每次都必须遵守 → 提示词；一类场景的完整手艺 → Skill；执行动作 → Tool。**

## 2. 独立成 Skill 的五问判断器

对一项候选能力依次问，五项都过才独立成 Skill：

1. **会重复使用吗？** 一次性指令 → 不建。
2. **有多个步骤、判断条件、例外吗？** 一两句话能说清 → 写提示词。
3. **只在特定任务用吗？** 每轮都用到 → 进提示词。
4. **需要独立维护吗？** 与基础规则强绑定 → 留在提示词。
5. **提示词负担大吗？** BASE_PROMPT 已约 22 KB；当规则开始互相干扰、难以维护的
   时候，是该 Skill 化的信号。

## 3. 主智能体禁入清单

以下内容**不做进主智能体 Skill**：

- 子智能体的专业能力（选品、比价辨析、送礼创意、归档方法）——主智能体的职责是
  「知道找谁、判断结果是否可用」，不是重做专业活
- 提示词职责的规范（收口结构、决策后话术、红线）——每轮必执行，归 BASE_PROMPT
- 运行时机制（工具权限、失败重试、状态恢复）——归代码
- 工具清单与调用细节——技能挂载机制会自动注入，不要手写

主智能体 Skill 的**合法形态只有两类**：

1. **复杂任务组织类**（规划 / 协作 / 审查）——当前均为候补（见 §7 台账）
2. **亲写交付场景类**——主智能体亲自产出的内容的手艺（如 `compare-two`：
   对比结论确由主智能体写，不是重复子智能体的能力）

## 4. Skill 文件怎么写

每个 Skill = `SKILL.md`（正文）+ `references/`（案例库、判据表，**按主题**组织）。

SKILL.md 至少包含：

1. frontmatter：`name`（与目录同名）、`description`（触发条件——写清「什么时候用 / 不用」）
2. 什么时候用 / 什么时候不用
3. 方法主体（步骤 + 判据 + 产出物）
4. 红线（真实踩过的坑，引用生产原文）
5. 自检清单

内容要求：

- 命名通俗实用（`price-check`、`compare-two` 风格），不要价值感命名
- 基于生产数据：案例引真实原文；统计数字注明口径、可复算
- **不重复提示词已有内容**——只补「提示词说不透的」（判例、决策树、好 / 坏样本）

## 5. 验证要求（改完必须做）

1. 组件级检查（清单能被扫描到、middleware 能构造）**不算验证**
2. 发真实对话 probe（图级即可，不经前端也行）→ 查两处证据：
   - checkpoint 里有没有模型 `read_file /skills/<name>/…` 的调用（它真的读了）
   - 行为是否真的变了（对照历史执行，如「同类输入此前会 X、现在会 Y」）
   - 操作提示：`checkpoint_writes` 表 `channel='messages'`（langgraph msgpack，
     用 `JsonPlusSerializer.loads_typed` 解码）查工具调用；`channel='skills_metadata'`
     查技能清单是否注入
3. 通过后才提交；验证方法与证据写进提交信息

> ⚠️ **已验证的坑**：`SubAgentMiddleware` 有两套代码路径（Legacy `default_model=…` /
> New `backend=…`），当前 master 走 Legacy 路径——技能挂载代码必须接在
> `_get_subagents_legacy` 里，只加在 New 路径上**不生效**（曾因此「接通」后从未加载）。

## 8. 候补台账（有触发条件的「未建清单」）

| 候补 | 触发条件（出现即立项） | 立项前先做 |
|---|---|---|
| `complex-task-planning` 复杂任务规划 | 出现**重复性**的「多步任务顺序错 / 漏步 / 重复派遣」失败，且根因归到规划 | 逐个样本根因归因。参照：2026-10 对「搜索 + 对比 + 推荐」组合任务 8 次执行的归因——6 次未完整收口，根因全部是数据源故障 / MCP 调用错误 / 会话中断，没有一次是规划错误，故未立项 |
| `cross-domain-orchestration` 跨 Agent 协作 | 出现「动态协作策略无法用稳定规则表达」的真实场景 | 先核对现有机制是否已覆盖：调度由 `SubAgentMiddleware` + `task` 工具实现，「该派谁 / 串并行 / 防重复」的规则在 BASE_PROMPT——**已覆盖的不重复实现** |
| `decision-review` 高价值决策审查 | 高成本决策出现「结论与目标脱节 / 证据不足 / 硬约束被违反」的漏检案例 | 先核对 BASE_PROMPT 自检 + 子智能体 risk 审计的覆盖度 |

**核查时机**：每次做 Agent 行为数据分析时，顺带对照本表一次；
命中触发条件时，先完成「立项前先做」列的功课，再动笔写 Skill 文件。
